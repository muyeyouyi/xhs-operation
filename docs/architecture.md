# AI 自媒体运营项目架构

更新日期：2026-11-11  
状态：SubGraph 版本。采用主图组合选题、写作和配图三个独立子图。

## 1. 目标与开发原则

用户先输入文案方向，AI 严格围绕该方向返回 3～5 个选题；用户选择后才生成文章，文章经过人工审核和修改后，制作 3～5 张图片。图片用于小红书，文章用于公众号，首期审核后导出、人工发布。

**全局贯彻代码精简、流程清晰、避免过度防御性编程，后续迭代同样遵守。** 不为尚未出现的需求预建微服务、空接口和多层转发。必要的边界校验、审核版本检查与失败恢复保留。

## 2. 运行结构

```text
Vue 3 + TypeScript
      │ HTTP（前端开发服务器代理）
      ▼
FastAPI ───────────────► 本地素材文件（只读访问）
      │                         ▲
      ▼                         │
PostgreSQL ◄────────────── 单 Python Worker
  ├─ content_tasks             ├─ LangGraph
  ├─ content_jobs              ├─ LLM API
  ├─ content_history           └─ Playwright 渲染与导出
  ├─ content_node_runs
  └─ LangGraph checkpoints
```

API 接收操作并将持久化任务入队，Worker 执行工作流。等待人工审核时保存检查点、结束本次调用，Worker 可以处理其他任务。

首期单 Worker 通过 PostgreSQL 会话锁互斥；进程退出后锁自动释放，新进程将 running 队列任务重置为 pending，并根据检查点继续。暂不引入 Redis、多 Worker 租约或跨服务调用。

API 不直接运行模型；工作流调用 LLM 和 Renderer；数据库访问集中在 Store。模型和渲染器通过构造参数传入工作流，方便替换供应商与测试，不额外建立抽象工厂或仓储接口层。

主图只负责 `topics → writing → images → export`，子图各自封装生成、人工审核及修改循环。子图工厂返回已编译的 LangGraph，可以独立调用或重新组合；共享 ContentState，嵌入主图后继承父级 checkpointer，并以子图命名空间隔离执行状态。当前串行组合，不加入通用编排框架。

## 4. 数据、接口与版本

创建任务时必填 `direction`，可选目标学员和参考素材，选题及图片数量均为 3～5，默认 4。未提供历史运营表现时不虚构热度数据。

业务库保存任务的当前状态、审核阶段快照和队列命令；LangGraph PostgreSQL 检查点保存完整执行状态。首版文章和卡片体量小，直接保存结构化内容，不另建内容版本仓储。审核恢复使用中断 ID，文章修改会增加版本并清空下游成品；历史快照保留旧稿。

子图暂停或失败时，主图状态不一定包含内部最新产出。Worker 通过 `current_snapshot` 合并最深活动子图内容用于展示，保留主图执行位置；审核恢复仍调用主图。历史快照使用内部最新检查点 ID，避免子图内多次退回时覆盖或遗漏版本。

本次直接切换子图结构，不迁移旧图状态；按用户要求清空本项目旧业务数据和检查点，保留表结构及检查点迁移元数据。原本地图片和日志不随数据库清理删除。

| 接口 | 功能 |
| --- | --- |
| `POST /api/v1/tasks` | 输入方向，创建任务 |
| `GET /api/v1/tasks` | 最近任务列表 |
| `GET /api/v1/tasks/{id}` | 当前状态、内容及审核 ID |
| `GET /api/v1/tasks/{id}/history` | 历史快照 |
| `GET /api/v1/tasks/{id}/metrics` | 实时节点状态、耗时、模型与 Token |
| `GET /api/v1/tasks/{id}/stream` | SSE 推送当前选题或文章的草稿快照 |
| `POST /api/v1/tasks/{id}/decisions` | 选题、通过、修改、人工编辑、取消 |
| `POST /api/v1/tasks/{id}/retry` | 重试失败任务 |
| `GET /assets/{path}` | 图片和导出包 |

写入任务与入队使用同一事务，API 返回后由前端轮询。审核请求检查阶段、操作和中断 ID，拒绝重复或旧请求。外部调用失败保留检查点，用户可以重试；不静默兜底为演示内容。

实际业务节点统一配置原生 RetryPolicy：首次执行加 5 次重试，间隔为 1、2、4、8、16 秒，无随机抖动。子图容器不叠加重试，人工中断不重试；耗尽后才由 Worker 将队列任务标记失败。每次尝试独立保存节点指标，自动重试不产生新 job_id；后续人工重试会创建新队列任务。

执行指标独立保存在 `content_node_runs`：每次节点调用先提交运行记录，再执行耗时操作，结束或人工中断时更新状态及单调时钟耗时。LLM 从实际响应记录 model 和 usage，即使正文格式校验失败也保留用量。节点通过 ContextVar 关联模型调用，Store 通过闭包注入，数据库对象不进入可持久化的图配置。

前端任务详情最上方每秒轮询指标，动态展示执行中时长。总计累加各次执行，不含人工等待；未知 Token 和中断耗时不虚构为 0。Worker 重启时将未完成的指标标记为中断，并按原逻辑恢复队列。上线前的执行不补算历史指标。

选题与写作的模型请求使用流式响应，只采集 delta.content，片段约每 0.2 秒合并写入对应节点的 output_text。API 通过 SSE 推送最新队列任务中最新尝试的草稿快照，连接重建直接发送当前快照；不增加 Redis 或事件重放表。每次重试有独立节点 ID，避免新旧文本拼接。指标接口排除正文，流式草稿不进入正式工作流状态；完整接收并校验后才将正式结果保存到检查点并开启审核。

## 5. 出图与导出

LLM 将已审核文章提炼成结构化卡片和小红书标题、短文案；HTML/CSS 模板经 Playwright 渲染为 1080×1440 PNG。卡片正文支持 Markdown 代码块、列表等，禁用原始 HTML。版面溢出回到成品审核，用户可要求精简后重新生成。

成品通过后导出 ZIP，包含小红书图片和发布文案、公众号 Markdown 与 HTML。同一内容版本使用固定文件路径，重试不会生成重复目录。

## 6. 当前边界与扩展

PNG 渲染采用异步 Playwright，共用一个浏览器、每张独立页面，以信号量限制并发（默认 3，配置范围 1～5）。同步 Worker 通过 `asyncio.run` 调用渲染器，不新增服务或线程池。模型仍一次生成整组卡片内容，图片按原始编号返回并导出；失败先清理在途渲染，再交给现有节点处理。

首期本机内部工具，不包含账号体系、平台自动发布、定时调度和自动采集。独立素材库、画像管理、反馈分析等模块尚未实现；本次通过任务中的目标学员和参考资料输入满足核心闭环。

人工编辑文章在文章审核阶段完成；成品阶段修改图片和渠道文案。完成后的任务不再恢复审核，需要改原文或方向时另建任务。

扩展遵循实际需求：新增渠道先扩展导出模块；新增模型先调整 LLM 适配器；数据结构发生变化再引入迁移；多人协作或多 Worker 需求明确后再增加权限与并发机制。

## 7. 验证

- LangGraph 流程测试：方向和 3～5 个选题、退回重写、人工编辑、成品修改、取消。
- 子图测试：三个子图独立运行、只组合选题与写作、各子图审核点重启恢复及内部版本历史。
- 恢复测试：旧命令重投不推进新审核点，重建图可恢复，渲染失败不重复写文章。
- PostgreSQL 集成：API 操作、事务入队、审核版本校验、新连接恢复和失败重试。
- 渲染与导出：中文和代码块、PNG 尺寸、内容溢出、双平台 ZIP 及 HTML 转义。
- 前端：TypeScript 检查、生产构建和本地页面操作。
