# 知页 · AI 自媒体内容工作台

面向 AI 编程培训公司的内部运营工具。用户先输入内容方向，AI 返回 3～5 个选题；人工选题后生成文章，经审核修改后制作 3～5 张图片，最终导出小红书与公众号素材。

## 开发原则

**代码精简、流程清晰、避免过度防御，后续迭代持续遵守。**

目前采用 Vue + FastAPI + LangGraph + PostgreSQL。同仓库、API 与单 Worker 分进程；选题、写作、配图分别为独立子图，主图只负责组合与导出。直接按职责划分模块，不预建多层架构或未使用的扩展接口。项目约定见 [AGENTS.md](AGENTS.md)。

## 本地启动

要求 Python 3.11+、uv、Node.js 20.19+ 或 22.12+、PostgreSQL。以下命令均从项目根目录执行。

1. 安装依赖，创建本地配置：

```sh
uv sync
cp .env.example .env
uv run playwright install chromium
```

编辑 `.env` 中的 `LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL`。模型接口需要支持 OpenAI-compatible Chat Completions 与 `response_format: json_object`；模型由你选择，应用不自动替换模型或返回演示数据。

使用火山方舟豆包时，配置示例：

```dotenv
LLM_BASE_URL=https://ark.cn-beijing.volces.com/api/v3
LLM_API_KEY=你的方舟API密钥
LLM_MODEL=你已开通的模型ID或推理接入点ID
```

`LLM_BASE_URL` 不包含末尾的 `/chat/completions`，代码会自动拼接。修改 `.env` 后重启 Worker，使配置生效；不需要额外安装方舟 SDK。

选题请求显式使用 `thinking.type=disabled` 关闭深度思考；使用精简 JSON 格式说明，标题、角度、推荐理由分别指导在 24、30、16 字内，每个选题预留 256 Token 输出预算。请求只传方向、读者及实际填写的参考资料/反馈，不传配图数量等无关信息。本地仍校验 JSON 和选题数量；模型返回长度截断时明确提示，不接收截断结果。

写作和配图摘要继续使用原提示词、完整 Schema 与模型默认思考设置。本轮不切换模型、不启用额外缓存；代码更新后由用户在自己的终端重启 Worker。

2. 启动 PostgreSQL 并初始化表：

先启动 Docker Desktop，再执行：

```sh
docker compose up -d postgres
uv run python -m media_ops.db
```

也可使用已有 PostgreSQL，修改 `DATABASE_URL` 后执行初始化命令。初始化支持重复执行，不会删除已有数据；当前首版使用建表 SQL，实际发生表结构变更时再引入迁移。

Worker 报 `Connection refused` 时，先用 `docker compose ps` 检查数据库是否运行，再执行上述命令。镜像下载受网络影响时，首次创建数据库可在 `.env` 中设置 `POSTGRES_IMAGE` 为本机已有镜像，例如 `postgres:15-alpine`。已有数据卷应继续使用其对应的 PostgreSQL 主版本。

3. 分别在三个终端启动 API、Worker 和前端：

```sh
uv run python main.py
```

```sh
uv run python -m media_ops.worker
```

```sh
cd frontend
npm ci
npm run dev
```

前端地址以 Vite 输出为准，默认 [http://127.0.0.1:5173](http://127.0.0.1:5173)。API 文档位于 [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs)。Vite 代理 `/api` 和 `/assets` 到后台；当前仅配置本地开发，不包含线上部署。

## 使用流程

1. 输入内容方向，按需填写目标学员与参考素材，选择 3～5 个候选选题、3～5 张图片。
2. 选择选题，或补充要求后重新推荐；此时不会提前写文章。
3. 查看文章，可提交意见让 AI 重写，或人工编辑并保存新版本；每次修改后重新审核。
4. 确认文章后生成图片、小红书标题与短文案；可按意见重新生成成品。
5. 成品通过后下载 ZIP：小红书 PNG 和发布文案、公众号 Markdown 与 HTML。

每个审核阶段均可取消。节点执行异常时先自动重试，耗尽后展示错误，仍可人工重试当前步骤；图片内容溢出会回到成品审核，填写精简要求后重新生成。历史记录保存每次审核阶段的内容快照。

## 选题与文章流式输出

选题生成和文章生成（包括按意见重写）使用模型 `stream=true`，页面通过 SSE 逐步展示“流式草稿”，不必等完整响应才看到文字。配图内容生成保持非流式。

- 草稿只展示标题、角度、推荐理由和文章正文，不展示 JSON 结构或思考内容。
- 模型正文片段约每 0.2 秒合并写入节点记录；API 每 0.25 秒检查变化，并通过 `GET /api/v1/tasks/{id}/stream` 推送最新草稿快照。
- 浏览器断线后自动重新连接，刷新后打开同一任务也能读取当前草稿；连接断开不取消后台生成。
- 每次重试对应独立节点记录，新尝试会替换旧草稿，不能混合展示。页面上的草稿不能直接选择或审核；完整响应通过 JSON、字段与数量校验后，才进入原有人工审核流程。
- 流式请求设置 `stream_options.include_usage=true`，在响应结束时保存实际 Token 用量。连接提前结束或输出截断会触发现有节点退避重试。
- `content_node_runs.output_text` 保存正文草稿，指标接口不返回该字段；增量建表保留已有数据，旧节点没有流式历史。启动新环境仍执行 `uv run python -m media_ops.db`。

前端新增 `partial-json` 用于解析尚未闭合的 JSON，后端最终校验仍由 Pydantic 完成。更新后前端依赖执行 `npm ci`，由用户自行重启 Worker，并刷新页面。

## 图片并行渲染

配图先由模型一次生成整组卡片内容，再用一个 Chromium 浏览器、独立页面并行渲染 PNG。默认最多同时渲染 3 张；`.env` 可设置 `RENDER_CONCURRENCY=1`～`5`，设为 1 即串行。由用户自行重启 Worker 后生效。

图片始终按原卡片顺序返回，尺寸仍为 1080×1440。单张失败会取消并等待其他渲染结束，再关闭浏览器；普通异常沿用节点重试，内容溢出仍回到人工审核。日志增加每张图片的开始、完成和耗时，节点指标仍统计整组渲染耗时。

本机同一组 5 张公开测试卡片交替运行 3 轮：串行中位数 0.990 秒，并发 3 张为 0.722 秒，渲染阶段约减少 27%。此对比使用新版渲染器的并发配置 1 与 3，不代表整个配图流程的加速比例；此前实际任务主要耗时在模型整理卡片内容（约 13～18 秒），本次没有拆分或增加模型调用。

## 节点自动重试

每个实际业务节点使用 LangGraph 原生 `RetryPolicy`：首次执行失败后，最多再重试 **5 次**，即最多执行 **6 次**。等待间隔固定为 **1、2、4、8、16 秒**，指数因子为 2，不添加随机抖动；累计退避最多 31 秒，不含节点本身的执行耗时。

- 覆盖选题、写作、配图子图内所有节点及主图导出节点；子图容器不额外添加重试，避免次数叠加。
- 节点抛出的普通异常均适用，包括模型请求、输出校验和文件处理异常；人工 `interrupt` 暂停与正常取消不触发重试。
- 仅重试失败节点，已完成的上游节点不会重新生成；重试耗尽后保留检查点，任务标记失败，可由人工重新发起。
- 自动重试沿用本次 `job_id`，各次尝试独立记录节点耗时和实际 Token。节点总耗时不含退避等待，本次队列任务耗时包含等待。
- 中文日志显示“将在 N 秒后进行第 X/5 次重试”和次数耗尽信息；最后一次失败由 Worker 输出错误堆栈。

代码更新后由用户自行重启 Worker 生效。

## 节点执行指标

任务详情最上方展示实时指标，每秒自动更新：总耗时、总 Token、已执行节点数，以及每次节点执行的中文名称、子图、状态、耗时、输入/输出/总 Token 和模型。

节点开始时写入 `content_node_runs`，完成后更新；页面在模型调用尚未结束时也能显示当前节点和增长中的耗时。接口为 `GET /api/v1/tasks/{id}/metrics`，最新执行记录显示在前。

- 总耗时是所有节点执行时长之和，不包含人工等待；执行中时长由启动时间动态展示。
- 已执行节点数包含完成、失败和中断的执行次数，重复运行分别计数；正在执行或等待审核的调用不计入。
- Token 使用模型实际返回的 `usage`，不按字数估算。执行中显示“统计中”，接口未提供用量时显示“未提供”，不调用模型的节点显示“—”。部分调用缺失用量时，总计只统计已知值并提示。
- 模型返回后即记录用量，因此输出格式校验失败的调用仍保留已消耗 Token。每个生成节点的单次尝试调用一次模型。
- Worker 重启后，未结束的节点记录标记为“执行中断”；无法确认的中断耗时不计入总耗时。
- 新功能上线前已执行的节点没有指标记录，不回填或伪造历史用量；后续执行和重试会正常采集。

## 执行日志

日志同时输出到 Worker 终端和工程根目录的 `logs/worker.log`，目录自动创建，使用 UTF-8 编码，重启后追加写入。日志目录与可下载的素材目录分开。

日志采用中文描述，去掉进程和 Python 线程信息，保留以下定位信息：

- `流程`：原 `thread_id`，与内容任务 ID 相同，串起一次完整内容生产。
- `执行`：原 `job_id`，标识本次队列任务；人工审核恢复时会产生新值。
- `子图`：当前能力模块，例如“选题”“写作”“配图”；导出标记为“主流程”。
- `节点`：当前执行步骤的中文名称，例如“生成候选选题”“审核文章”“渲染图片”。
- `耗时`：当前节点本次执行的秒数；`本次耗时` 是本次队列任务的处理时间。

示例省略完整流程 ID：

```text
2026-11-11 12:30:00,000 INFO 流程=... 执行=10 开始处理 类型=创建内容
2026-11-11 12:30:00,001 INFO 流程=... 执行=10 子图=选题 节点=生成候选选题 开始执行
2026-11-11 12:30:03,259 INFO 流程=... 执行=10 子图=选题 节点=生成候选选题 执行完成 耗时=3.258秒
2026-11-11 12:30:03,260 INFO 流程=... 执行=10 子图=选题 节点=选择选题 等待人工操作 耗时=0.001秒
2026-11-11 12:30:03,300 INFO 流程=... 执行=10 等待人工操作 阶段=选择选题 本次耗时=3.300秒
2026-11-11 12:35:00,000 INFO 流程=... 执行=11 恢复流程 操作=选择选题
2026-11-11 12:35:00,002 INFO 流程=... 执行=11 子图=写作 节点=生成或修改文章 开始执行
```

耗时使用单调时钟，不包含人工等待。异常保留错误类型和堆栈，便于排查；不输出密钥、完整文案、素材或审核意见。`INFO`、`ERROR` 及异常类名保留标准名称。

修改代码后重启 Worker 生效，新日志继续追加，原有日志不改写。实时查看文件：

```sh
tail -f logs/worker.log
```

## 核心代码

```text
backend/media_ops/
├── api.py          # HTTP 接口
├── worker.py       # 持久化任务执行、检查点恢复
├── workflow.py     # 主图：子图组合、导出与状态投影
├── graphs/
│   ├── common.py   # 共享状态、人工等待与中文节点日志
│   ├── topics.py   # 选题子图
│   ├── writing.py  # 写作子图
│   └── images.py   # 配图子图
├── db.py           # PostgreSQL 任务、队列、历史
├── metrics.py      # 当前节点上下文、模型用量采集
├── streaming.py    # SSE 草稿快照推送
├── models.py       # 输入与模型输出结构、审核动作校验
├── llm.py          # 选题、文章、成品生成
├── rendering.py    # 卡片渲染、双平台导出
├── config.py       # 环境配置
└── templates/card.html
frontend/src/       # Vue 工作台、API 类型、样式
tests/              # 流程、数据库集成、渲染与导出测试
```

工作流说明见 [docs/workflow.md](docs/workflow.md)，架构与边界见 [docs/architecture.md](docs/architecture.md)。

三个子图工厂均返回编译后的 LangGraph，支持独立运行，也可直接作为其他图的节点。嵌入主图时继承父图检查点；独立运行时传入 checkpointer。复用与组合示例见工作流文档。

## 验证

```sh
uv run pytest -q
cd frontend
npm run build
```

默认测试使用替代 LLM，不消耗真实模型额度。真实数据库集成测试需要独立测试库，真实渲染测试需要 Chromium：

```sh
TEST_DATABASE_URL=postgresql://media:media@localhost:5432/media_ops_test RUN_RENDER_TESTS=1 uv run pytest -q
```

先创建测试库；没有设置对应变量的测试会跳过。测试库将保存测试任务与检查点，请勿指向正式业务库。

## 当前边界

- 单公司、本机内部工具；无账号体系、权限管理与公网部署配置。
- 单 Worker 通过 PostgreSQL 会话锁互斥，进程重启时回收未完成的队列任务；首期不做多 Worker 租约。
- 审核绑定 LangGraph 中断 ID，重复或旧审核请求拒绝；重投原队列命令不会推进新审核点。
- 文章和卡片数据保存在检查点及业务快照中；当前内容体量小，暂不拆分独立内容仓储。
- 当前主图串行组合三个子图。业务展示读取活动子图状态，历史记录绑定内部最新检查点；暂不引入并行子图的状态合并策略。
- 本次子图结构切换不兼容旧流程检查点，按用户要求清空旧业务数据和检查点；保留表结构及检查点迁移元数据。
- 人工编辑文章在文章审核阶段进行。成品阶段可以按意见修改卡片和渠道文案；完成后如需换方向或改原文，另建任务。
- 不包含热点采集、定时任务、平台自动发布、独立素材库与反馈分析；参考资料通过创建任务时输入。
- 模型输出校验失败按节点策略重试，耗尽后展示错误并允许人工重试，不增加独立的自动修复链。技术准确性仍由运营审核。
